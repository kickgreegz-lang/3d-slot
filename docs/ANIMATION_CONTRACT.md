# Animation contract

This is the **binding interface between the art pipeline and the runtime**: names, frame windows, events, bones, clips, ids and feel constants. Both sides follow it:

- **Art side.** Generators emit these names and gates enforce them:
  - [`tools/spine/gen.py`](../tools/spine/README.md) generates Spine skeletons, and `tools/spine/validate.mjs` gates them;
  - [`tools/blender/build_actions.py`](../tools/blender/README.md#animation-json) builds mascot clips, gated by `pnpm anim:check`;
  - `tools/blender/render_symbol.py` renders baked inserts, with its own gates;
  - [`tools/gltf/budget.mjs`](../tools/gltf/README.md) gates GLB budgets.
- **Runtime side.** `src/` reads these names.

When the two disagree, fix the side that is wrong. Do not add a third name.

Sources of truth in the repo:

| Concern | File |
|---|---|
| Symbol ids, kinds, `restAngle`, `cellScale`, win tiers, spot bands | `src/config/game.ts` |
| Feel constants (ms, px, px/s²) | `src/core/timing.ts` (`TIMING`) plus each module's table registered with `registerTiming` (`TIMING_SECTIONS`: board, symbol, HUD, presentation, FX, audio, scene). **Every section is tunable live in `?dev=lab`** and exported from there |
| Scene events, `MascotCue`, `SfxId` | `src/game/events.ts` |
| Spine runtime binding | `src/symbols/SpinePool.ts` (`SPINE_EVENT`, `SPINE_ANIM` name aliases, per-pair mixes), `src/symbols/SymbolRig.ts`, `src/symbols/symbolTiming.ts` |
| **Machine-readable copy of §2–4** (windows, events, budgets, physics presets, runtime aliases, `timing.runtimeKickMax`) | [`tools/spine/contract.json`](../tools/spine/contract.json). Both `gen.py` and `validate.mjs` read it. **Change it in the same PR as this document** |
| Mascot animation JSON format | [`tools/blender/anim.schema.json`](../tools/blender/anim.schema.json) |
| Mascot clip state machine | `src/mascots/MascotController.ts`, `src/mascots/Mascots.ts`, `src/mascots/procedural.ts` |
| Art provider (texture keys, 360 px canvas) | `src/assets/art.ts` |
| Audio manifest (`SfxId` → files, music stems) | `src/audio/manifest.ts` |

Pinned versions: Spine Editor **4.3.x** (one patch, never a beta), runtime `@esotericsoftware/spine-pixi-v8` **4.3.13**, three **0.186**, pixi.js **8.21**, GSAP **3.15**. Everything is authored at **30 fps**.

Status tags used below:
- **[ok]**: the runtime already reads it.
- **[delta]**: the runtime needs a small change (listed in [§10](#10-runtime-conformance-checklist-for-src-owners)).
- **[planned]**: nothing reads it yet.
- **OPEN DECISION**: the pipeline and the runtime or art bible disagree, and the user or art lead must choose. The options are listed where the tag appears.

Open decisions: [§3.1 the `land` cell gate](#31-land-contact-frame-and-cell-gate-open-decision) and [§7.4 which morph targets are required](#74-morph-targets--15).

Research background: [research/stack-final.md § animationContract](research/stack-final.md). This document reconciles that research with the code that exists.

## 2. Spine symbol skeletons (4.3 JSON)

### 2.1 Files

```
art/source/symbols/<ID>/{master_2048.png, master.psd, parts.json, rig.yaml}   # inputs (git-LFS)
art/source/spine/images/sym_<ID>/<part>.png                                    # parts, 2x, 2–4 px padding
build/spine/sym_<ID>.json          # generated by tools/spine/gen.py (gitignored)
art/source/spine/sym_<ID>.spine    # canonical project (git-LFS), via Spine CLI import
public/assets/spine/sym_<ID>.skel  # binary export
public/assets/spine/symbols.atlas + symbols.png (+ symbols@0.5x.*)   # ONE shared atlas, PMA
config/spine/pack-symbols.json     # pack settings (not created yet; tools/spine/export.sh falls back to tools/spine/config/pack-symbols.json)
```

> Path fix: the attachment path is `sym_<ID>/<part>`, so the images root must be `art/source/spine/images/`. That root makes both the skeleton `images` path and the CLI pack input `-i art/source/spine/images` resolve. It supersedes the research's `art/source/spine/<skel>/images/`. In `art/source/symbols/<ID>/parts.json` this is `"images": "../../spine/images"`; `gen.py -o build/spine/sym_<ID>.json` then writes the `skeleton.images` value of §2.2.

### 2.2 Header and coordinates

- `skeleton: { spine: "4.3.<pinned>", fps: 30, referenceScale: 100, images: "../../art/source/spine/images/" }`.
- **Canvas.** The skeleton is authored on the **360×360 @2x symbol canvas**, the same canvas as the static texture (`SYMBOL_TIMING.spine.canvasPx = 360`). **`root` sits at the canvas centre**, which is the texture's anchor (0.5, 0.5).
- **Axes.** Author in **Y-up**. The runtime skeleton is y-down, so in `physicsTranslate` +y means **down**.
- **Scale.** Export at **scale 1.0 of the @2x art**. Pack at `scale: [1, 0.5]`, which gives `symbols.atlas` and `symbols@0.5x.atlas`. Never export Spine at 1x into a folder that AssetPack also mip-maps.
- **Pack settings.** `premultiplyAlpha: true`, max 2048×2048, `pot: false`, padding 2, `edgePadding`, strip whitespace, rotation, `packing: "polygons"`, linear filtering. Region names carry **no file extension**.

### 2.3 Bones

| Bone | Where | Purpose |
|---|---|---|
| `root` | Canvas centre | Never animated by symbol clips |
| `squash` | Bottom-centre of the art's content bounds (≈ cell bottom edge, y = −150 @2x for full-height symbols) | Pivot for **all** squash and stretch, so it matches the runtime body pivot "at the feet" |
| `body` | Child of `squash` | Carries the art; parts hang below it |
| `ctrl_*` | Anywhere | Driven at runtime (look-at, sliders) |
| `ik_*` | Anywhere | IK targets |
| `phys_*` | Appendages (antennae, cable, chain, sauce) | Physics-driven; each physics constraint has the **same name as its bone** |
| `face_*` | Eyes, lids, mouth | Face states (track 2) |
| `fx_*` | Children of `root` | Glows and sparkles (additive slots only) |

Bone names are `snake_case`. L/R means the character's own left and right.

### 2.4 Slots, attachments, skins

- A slot is named after its main attachment. The attachment path is `sym_<ID>/<part>`, for example `sym_H3/claw_L`.
- The blur variant is `<part>_blur`, a region attachment swap. **No sequence attachments** until spine-pixi-v8 ≥ 4.3.14 ships fix #3162 and passes a batching test.
- Additive blend only on `fx_*` slots.
- Skins: `default`, plus optional `gold`, `sticky`, `mystery`.
- **No clipping attachments.** The board is masked in Pixi.

### 2.5 Constraints and physics

- There is one root `constraints[]` array (4.3 format), evaluated in order: **IK → transform → physics**.
  - A 4.2-format file (separate `ik`/`transform`/`physics` arrays) loads in 4.3 with **every constraint silently dropped**. The validator rejects it.
- Physics defaults, with ω = 2πf:
  - `strength = ω² · mass`
  - `damping = exp(−2ζ · ω / 60)`
  - fps 60, inertia 0.5–0.8

  | f (Hz) | ζ | strength | damping | Use |
  |---|---|---|---|---|
  | 3.0 | 0.20 | 355 | 0.882 | Long, floppy (cable, chain) |
  | **3.5** | **0.25** | **484** | **0.833** | **Default** |
  | 4.0 | 0.30 | 632 | 0.778 | Short, stiff (antenna tip) |

  The editor default of 100 / 0.85 is about 1.6 Hz and floaty. Do not ship it.

  The generator's presets (`floppy`, `default`, `stiff`, `jelly`, in `tools/spine/contract.json`) implement this table. The validator prints the implied Hz and ζ of every constraint. It flags the editor default, and **warns** when inertia is outside 0.5–0.8 or the implied frequency is outside 2–8 Hz.
- **`limit`** (skeleton units) must be at least the maximum fall speed, otherwise the drop is clipped.
  - Our art is @2x (2 skeleton units per design px) and the drop `vMax` is 5,250 design px/s, so limit ≥ 10,500. Use **12,000**.
  - The research figure of ~20,000 assumed 512 px authoring.
- **Curves** are always computed in code as absolute beziers: 4 numbers per channel, 8 for 2-channel timelines. Every weighted vertex needs at least one bone.

### 2.6 Budgets (per symbol, validator-enforced)

≤ 30 bones · ≤ 250 mesh vertices · ≤ 8 slots · 0 clipping attachments · parts at 2x with 2–4 px padding. `tools/spine/validate.mjs` enforces all of them except the padding.

## 3. Symbol animations

All times are at 30 fps (`f` = frames). "Required" means the validator fails the skeleton if the animation is missing. The runtime itself falls back to its procedural rig for any missing animation, so a partial skeleton never breaks the game.

| Name | Loop | Window | Required for | Events | Rules | Runtime |
|---|---|---|---|---|---|---|
| `idle` | yes | 60–120 f (2–4 s) | H1–H4, W, S | none | First key equals last key. | [ok] The runtime plays it **once** per idle accent, on symbols the board picks at random (`SymbolRig.idleAccent`), so the grid never breathes in unison. It does not loop it or randomise `trackTime` |
| `land` | no | 9–15 f (300–500 ms) | H1–H4, W, S | `land_impact` on the contact frame, which is **frame 0** | **Frame 0 is the contact frame.** Squash on the `squash` bone to sy 0.83–0.87 with sx = 1/√sy, one rebound, ends on the setup pose. Stays inside the cell bounds: **OPEN DECISION**, see [§3.1](#31-land-contact-frame-and-cell-gate-open-decision). | [ok] `land_impact` and the legacy `impact` both accepted |
| `win` | no | 18–27 f (600–900 ms) | H1–H4, W, S | `win_peak` | Anticipation dip, pop to ~125%, settle to ~110%. Last frame equals frame 0 of `win_loop` (mix 0). Must fit `TIMING.win.winAnimDuration` = 900 ms. | [ok] `win_peak` moves the sparkle burst onto the pop apex |
| `win_loop` | yes | 30–60 f (1–2 s) | H1–H4, W, S | none | Seamless. | [ok] queued after `win` |
| `anticipation` | yes | 12–24 f; one beat ≈ `TIMING.anticipation.pulsePeriod` (520 ms ≈ 16 f) | W, S (and a bonus symbol if added) | optional `sfx` | Tension pulse + glow. | [ok] accepted as the loop (alias of the legacy `anticipation_loop`) |
| `anticipation_intro` | no | ≈ 9 f (`TIMING.anticipation.introDuration` 300 ms) | optional | none | Into the loop pose. | [ok] |
| `anticipation_out` | no | ≈ 7–8 f (`outroDuration` 250 ms) | optional | none | Back to setup pose. | [ok] |
| `explode` | no | 9–18 f (300–600 ms) | H1–H4, W, S | `explode_burst` (target frame 2–3, ≈ `TIMING.explode.anticipateDuration` 80 ms), `explode_done` | Ends at alpha 0. | [ok] `explode_burst` and the legacy `burst` both accepted; `explode_done` ends the state and returns the instance early |
| `appear` | no | 6–12 f | optional | none | Cascade drop-in accent. Drops themselves are code-driven. | [planned] |
| `blur` | yes | 1–2 f | H1–H4, W, S | none | Swaps region attachments to `<part>_blur`. | [ok] (else the `_blur` texture) |
| `dim` | overlay | any | optional | none | Track 1 only, never track 0. The runtime tints by default (`TIMING.win.dimTint`). | [planned] |
| `reveal`, `expand`, `sticky_lock`, `upgrade` | no | as designed | optional (math-dependent) | as designed | Mystery / expanding wild / sticky / upgrade. | [planned] |
| `fx_glow` | overlay | any | optional | none | Track 1, `entry.additive = true`. | [planned] |
| `blink` | overlay | 3–6 f | optional | none | Track 2. | [planned] |

**Tracks:** 0 = state · 1 = additive FX or dim · 2 = face/blink · 3 = look/talk.

**Mixes:** `defaultMix` 0.08; `land→idle` 0.15; `idle→win` 0.06; `win→win_loop` 0; `any→explode` 0.05; `blur↔idle` 0.
- **[ok]** `SpinePool` sets `defaultMix` from `SYMBOL_TIMING.spine.mix` (0.08) and every pair above from `SYMBOL_TIMING.spine.mixes`, for the animations a skeleton has. Both are tunable in `?dev=lab` (section `symbol`).

**Validator rules** ([`tools/spine/validate.mjs`](../tools/spine/README.md#validatemjs), on `@esotericsoftware/spine-core` 4.3.13; `pnpm spine:validate <skeleton.json> [--atlas …] [--kind …] [--cell …] [--kick …] [--report …] [--strict]`):
- no NaN. Every animation is stepped with physics at 60 Hz;
- the loop seam is sampled with `loop=false`; end poses match (loops end on their first key, `win` on `win_loop`'s first pose, `land`/`appear`/`anticipation_out` on the setup pose, `explode` at alpha 0);
- events are checked by stepping **2 frames past the end** (last-frame events fire on the next update); `explode_burst` must land on frame 2–3;
- duration windows as above, and `win` ≤ 900 ms;
- **`land` squash depth:** sy 0.83–0.87 on the `squash` bone (outside it: warning), inside the 0.80–0.88 feel gate (outside it: error), and sx = 1/√sy (warning beyond ±0.03);
- **`land` stays within the cell** with the physics kick applied in both directions. The default kick is **±36** skeleton units (`contract.json` `timing.runtimeKickMax`): the runtime's 26 × the largest land multiplier 1.378, a `special` landing at maximum velocity. See [§3.1](#31-land-contact-frame-and-cell-gate-open-decision);
- budgets from §2.6;
- the 4.3 constraint format and order (IK → transform → path → physics → slider); physics pairing and warnings from §2.5;
- no sequence attachments; region names without extensions; additive blend only on `fx_*` slots;
- `sfx` payloads are `SfxId`s (parsed from `src/game/events.ts`); `vfx` payloads are FX ids.

Exit codes: 0 pass, 1 fail (with `--strict`, warnings also fail), 2 usage.

### 3.1 Land: contact frame and cell gate (OPEN DECISION)

**Resolved: frame 0 is the contact frame.** `land` starts at the moment the symbol touches down, and `land_impact` is keyed on frame 0 (the generator's `impact_frame` is 0). The runtime does both things at contact (`SymbolRig`):
- it kicks the physics (`SpineRig.impact`) and starts `land` in the same step;
- it plays the land feedback (SFX, dust, shake) on `land_impact`, or immediately when the skeleton has no such event.

Do not author a pre-contact fall inside `land`: the drop itself is code-driven.

**Open: the "`land` stays inside the cell" gate conflicts with the runtime fit and the art bible.**
- **The validator** checks the literal rule: the land pose, with the ±36 kick applied, stays inside a fixed ±150 skeleton units around `root` (the 300-unit cell at @2x).
- **The runtime** (`SymbolRig.fit()`) rescales every rig so its rest content fills `cellScale` of the cell: highs 0.95–0.97, specials 1.02–1.12. The [ART_BIBLE](ART_BIBLE.md) cellFill says the same: highs 288–300 px, specials 306–345 px @2x.

The consequences:
- **Authoring smaller buys no headroom in game.** The demo rig passes the gate only because it is 257 px tall (86%). In game it is scaled ×1.27, and `land` rises 9.8% of the cell above the top.
- **A special sized to the art bible fails at rest.** Tested: the demo scaled to 331 units leaves the cell by 37.8 units before any animation.
- **A high at ~97% fill plus the 6% rebound stretch** also leaves the 300-unit cell.

Options for the user / art lead:
1. **Allow overflow** into the gap between cells (and over the frame, via `winLayer`) up to a defined margin, and gate against that margin.
2. **Cap the rebound and stretch** so the in-game land pose stays within the cell. This does not work for specials, whose rest pose already exceeds the cell (`cellScale` > 1).
3. **Require headroom**: lower the art-bible cellFill and/or `cellScale` so every symbol fits the cell when it lands.
4. **Gate relative to the fitted rest silhouette** instead of the fixed cell: e.g. the land pose may exceed the rest bounds by at most X% of the cell height. The validator already prints a `runtimeFit` line with the in-game numbers.

Until this is decided, the validator keeps the literal gate. Pass `--cell <units>` for specials and review the `runtimeFit` line. The same numbers bound the §9 rebound gate (≤ 8% SH).

## 4. Events

| Event | Payload | Meaning | Runtime use |
|---|---|---|---|
| `land_impact` | none | Contact frame of `land` | Land SFX (`land_<weight>`), dust puff, board thump |
| `win_peak` | none | Pop apex of `win` | Sparkle burst, win SFX accent |
| `explode_burst` | none | Symbol breaks apart | `fx:burst` kind `explode`, `explode` SFX |
| `explode_done` | none | Symbol fully gone | Release the pooled instance early |
| `sfx` | string = an **`SfxId`** (§8.3), no take suffix | Play a cue; the runtime picks a take (round-robin) | `game.broadcast('sfx', {id})` |
| `vfx` | string = an **FX id** (§8.2) | Fire a live effect at the symbol | `fx:burst` / FX registry |
| `shake` | float = trauma to add, 0–1 | Camera trauma | `fx:shake` |
| `title_hit` | none | UI skeletons: title lands | Punch + shake |

Validators step 2 frames past the end, because events keyed on the last frame fire on the next update.

## 5. Runtime binding (spine-pixi-v8 4.3.13)

```ts
const spine = new Spine({ skeleton, atlas, autoUpdate: false });   // [ok] SpinePool; also sets defaultMix 0.08 + the §3 per-pair mixes
spine.update(gameDt * speedScale());                               // [ok] stepped from core/clock (hit-stop aware)

// spinning
spine.state.setAnimation(0, 'blur', true);                         // [ok]
spine.skeletonPhysics.setPositionInheritance(0, 0);                // [ok] SpineRig.detachPhysics: parts do not fly off during the spin

// reel stop (contact frame = land frame 0)
spine.skeletonPhysics.resetTransform();                            // [ok] SpineRig.impact
spine.skeletonPhysics.setPositionInheritance(0, 0.6);              // [ok] SYMBOL_TIMING.spine.landInheritance: container motion drives the jiggle
spine.skeleton.physicsTranslate(0, -26 * m);                       // [ok] physicsImpulse 26 × land multiplier m (≤ 1.378); up in y-down, see §10.4
const e = spine.state.setAnimation(0, 'land', false);
e.mixInterpolation = Interpolation.smooth;                         // [ok]
spine.state.addAnimation(0, 'idle', true, 0);                      // runtime differs: it releases the rig back to the static sprite after land

// win
spine.state.setAnimation(0, 'win', false);
spine.state.addAnimation(0, 'win_loop', true, 0);                  // [ok]

// idle: the runtime plays `idle` once per idle accent on randomly picked symbols (no trackTime randomisation)

// returning a pooled instance
spine.skeleton.setupPose();                                        // [ok]
spine.skeletonPhysics.resetTransform();                            // [ok]
spine.skeleton.updateWorldTransform(Physics.reset);                // [ok]
```

- **Global physics tuning** edits `constraint.data.setupPose.*`, because the live pose is reset each time.
- **Baked 3D turns and shatters** (§8.1) are Pixi `AnimatedSprite`s attached with `spine.addSlotObject('fx_slot', sprite)`. The `squash` bone and physics therefore still move them.
- **The symbol view** (`SymbolRig`) owns container-level drop, land squash and overshoot. Spine owns the inner parts. When a Spine `land` also squashes, the runtime halves its own body squash (`SYMBOL_TIMING.spine.squashScale = 0.5`).
- **Name aliases.** `SPINE_EVENT` and `SPINE_ANIM` in `SpinePool.ts` accept both the contract names (`land_impact`, `explode_burst`, `anticipation`) and the legacy ones (`impact`, `burst`, `anticipation_loop`). Generated rigs therefore need no `compat.runtime_aliases`.
- **In-game check of a generated rig without touching `src/`:** in DEV, `?spineDemo=<symbolId>` binds the demo rig (`public/assets/spine/demo/`) to that symbol (`src/assets/loader.ts`). `vite build` drops the demo from `dist/`. Production rigs are registered in `ART_MANIFEST.spine` (`src/assets/manifest.ts`).

### 7.4 Morph targets (≤ 15)

Required: `blink_L`, `blink_R`, `smile`, `frown`, `surprised`, `angry`.
Optional: `squint`, `mouth_open`, `mouth_O`, `mouth_E`, `brow_up`, `brow_down`.

The runtime expression layer (`procedural.ts`) matches names by regex:
- `blink|eyes_closed` → blink
- `happy|smile|joy` → happy
- `surpris|wow|shock` → surprised
- `sad|frown` → sad
- `angry|mad` → angry

So `smile` drives *happy* and `frown` drives *sad*. **`surprised` and `angry` must exist** or those expressions do nothing. (The research list lacked them.)

**OPEN DECISION: which morphs the gate requires.** This section lists six required morphs, but `tools/gltf/budget.mjs --mascot` (the step 4.4 gate) **fails** only when `surprised` or `angry` is missing. It only **warns** for `blink_L`, `blink_R`, `smile` and `frown`. Options for the user / art lead:
1. **Keep all six required.** Make the four warnings failures in `budget.mjs`.
2. **Require only `surprised` and `angry`,** the ones the runtime needs for expressions it has no other way to show, and demote `blink_L`, `blink_R`, `smile` and `frown` to "recommended" here.

Until this is decided, the gate behaves as option 2 and this list still reads as option 1.

### 7.5 Bones and meshes

- Export **deform bones only** (Rigify `DEF-*`), **renamed on export** so the procedural layer finds them. It looks for:
  - `hips` (or `pelvis`)
  - `spine` (or `spine_01`, `abdomen`)
  - `chest` (or `upper_chest`, `spine_02`, `torso`)
  - `neck`
  - `head`

  Keep limb names readable (`upper_arm_L`, …). The `DEF-` prefix and Rigify's `spine.00N` names do **not** match those regexes.

  `tools/blender/export_glb.py --rigify-names` (and `build_actions.py --export-glb … --rigify-names`) does the rename. It produces `hips`, `spine`, `chest`, `upper_chest`, `neck`, `neck_01`, `head`, and `DEF-x.L` → `x_L`. A Rigify control bone that already holds one of these names is moved aside to `<name>_ctrl`. Otherwise Blender would silently name the deform bone `hips.001`, which three.js turns into `hips001` and the runtime never finds. Control bones are not exported. A deform-bone collision is an error.
- Spring chains are named `spring_<part>_<n>`, where `<part>` is one of `tail`, `ear`, `jowl`, `belly`, `antenna`, `chain`. Only those words are picked up.
  - Gumbo: `tail`, `jowl`, `belly`.
  - Croak: `jowl` (throat pouch), `chain`, `belly`.
  - Wiggle is **never baked** onto spring bones; `@pixiv/three-vrm-springbone` simulates them at runtime.
- Keep meshes `eye_L`, `eye_R` and `mouth_*` separate (`gltf-transform … --join false`). Pupils use a UV-offset atlas.

### 7.6 Budgets and material

These are enforced by `tools/gltf/budget.mjs` (run by `pnpm gltf:optimize … --mascot`; exit 3 on a breach):

- **Geometry:** < 15k triangles, 30–60 bones (≤ 65; outside 30–60 only warns), 4 weights per vertex (`JOINTS_1`/`WEIGHTS_1` fail), 1–2 draw calls (`--mascot` fails above 2). No Draco (the runtime ships no decoder).
- **File size:** ≤ ~1.5 MB per GLB (the gate uses 1.5 MiB).
- **Clips and morphs:** `--mascot` also requires the 8 canonical clips of §7.2 and the morphs of §7.4 (see the open decision there).
- **Texture:** 1024 px palette texture, 4–8 flat toon colours. The AI texture's baked lighting is discarded (`tools/blender/cleanup_mascot.py`).
  - Default: `--texture-compress webp` (`tools/gltf/optimize.sh`, with `--palette false` so material names survive).
  - KTX2/UASTC only once the runtime **self-hosts the Basis transcoder** (then `optimize.sh --texture-compress ktx2 --allow-ktx2`; `budget.mjs` fails KTX2 without `--allow-ktx2`). The default transcoder path is a public CDN, which fails Stake's no-external-request rule.
  - Set `colorSpace = NoColorSpace` on GLB textures (gamma-space toon pipeline).
- **Runtime look:** `MeshToonMaterial` with a 3-step `NearestFilter` gradient `[90,170,255]`, a key light from the top-left plus hemisphere fill, `OutlineEffect` in `#000` at ~3 px on screen, and a blob shadow sprite in Pixi.
- **Render targets:** 512×768 at 4× MSAA on the high tier; 341×512 at 2× MSAA and 30 fps on the low tier; **off** in the compact/popout layout.
- **Proportions: adult only.** Head ≈ ¼ of height. Stake rejects child-like characters.

## 8. Baked frames, FX ids, audio cue ids

### 8.1 Baked 3D inserts

Produced by [`tools/blender/render_symbol.py`](../tools/blender/README.md#render_symbolpy-baked-3d-inserts-pipeline-51-animation_contract-81) (`pnpm blender:symbol`).

- **Naming:** `build/frames/<ID>_<clip>/<ID>_<clip>_0001.png`, with clip ∈ `spin | turn | shatter`. Example: `W_turn_0017.png`.
  - `<ID>` is always the **game id**: `--glyph K` resolves to `L2` through `art/bible/artbible.json`, so its frames are `L2_turn_0001.png`.
  - `static` (one rest frame, the frame-1 reference) and an optional baked `land` also exist.
  - The frame folder holds **frames only**, because it is one AssetPack `{tps}` folder. Sidecars go to `build/qa/blender/<ID>_<clip>/{sheet.png, qa.json, anim.json, manifest.json}`.
- **Rendering:** 2x, then Lanczos down in premultiplied alpha. Bottom-centre pivot, 24 fps.
- **Loops are exact by construction:** angle = 2π·revs·(f−1)/F, so frame F+1 equals frame 1 (`spin` does 2 turns per loop).
- **Frame 1 must equal the static sprite** (`--static <png>` gate). A shatter shows the intact mesh until its burst frame (frame 3, the `explode_burst` beat), so frame 1 equals the intact render. After that the chunks fly, and the last frame is empty.
- **Shatter canvas:** `--canvas-scale` **1.6×** the static canvas, at the same pixel density, so the flying chunks are not clipped. It is recorded as `anim.json → canvasScale`. Display the clip at `canvasScale ×` the static canvas so the content scale matches.
- **`anim.json` fields:**
  - `id`, `clip`, `prefix`, `fps`, `frames`, `loop`, `size` (px);
  - `canvasScale` (1.0, or 1.6 for shatters);
  - `anchor` `[0.5, 0.5]`;
  - `pivot` (the object origin, bottom-centre, in normalised px);
  - `frameNames`, and a `note`.
- **Manifest row: one per clip folder**, not per frame.
  - `sha256` is the digest of the sorted `'<file>:<sha256>\n'` lines of the folder, and the id embeds it (`frames.l2_turn.<8 hex>`). An identical re-render keeps its id.
  - Other fields: `stage 3d-render`, `route blender`, `licenseId blender-5.2`.
  - `tools/video/record.py` uses the same folder digest, and the licence audit checks it for drift.
- **Packing:** trim with `tools/video/flipbook.py … --pivot bottom-center --expect-frames <F>` into one AssetPack `{tps}` folder per clip, 2048 pages. `tools/assets/pack.mjs` fails when an animation's length differs from its rendered frame count.
- **At runtime:** play as an `AnimatedSprite` attached via `addSlotObject`.
- **What gets baked:** only true 3D turns and shatters. Land squash and glint stay at runtime.

## 10. Runtime conformance checklist (for `src/` owners)

Small changes that let the art pipeline's output be used as intended. None of them break current behaviour. Status as of 2026-09-24:

1. **Event aliases. Done.** `SPINE_EVENT` in `SpinePool.ts` accepts `land_impact`/`impact` and `explode_burst`/`burst`. The runtime also reacts to `win_peak` (sparkle burst at the pop apex), `explode_done` (early release) and `sfx` / `vfx` / `shake` payloads.
2. **Anticipation name. Done.** `SPINE_ANIM.anticipationLoop` accepts `anticipation` as well as `anticipation_loop`.
3. **Physics binding. Done**, except the idle start phase:
   - `setPositionInheritance(0,0)` while spinning (`SpineRig.detachPhysics`), and `resetTransform()` + `(0, 0.6)` at stop (`SpineRig.impact`, `SYMBOL_TIMING.spine.landInheritance`);
   - `resetTransform()` + `updateWorldTransform(Physics.reset)` on release;
   - `mixInterpolation = smooth` on land;
   - the idle `trackTime` is **not** randomised. The runtime plays `idle` once per idle accent on 1–2 randomly picked symbols instead, so the grid does not breathe in unison (§3).
4. **Kick sign. Done in code; eye check open.**
   - `SpineRig.impact` calls `physicsTranslate(0, −26·m)`, where m is the land multiplier (≤ 1.378). That is up in the y-down runtime, the same sign as the research's `−impact·0.006` (≈ −27): the body jumps up relative to the parts, so the parts keep falling.
   - `tools/spine/preview/capture.mjs` uses the same sign.
   - Still to do: sign it off by eye in `?dev=lab&spineDemo=H1` → `symbolLand`. Appendages must overshoot **downward** past the contact frame, then spring back. Until then the validator checks the land pose with the kick in both directions (±36).

6. **Feel constants. Partly done.**
   - Done: the land spring retuned to 1400 / 24 (≈ 6 Hz, ζ 0.32, measured to pass the gates); shake `maxOffset` 22; the lab stiffness slider raised to 4000; jurisdiction flags honoured; `FX_TIMING.flash` defaults.
   - Still open, from the "Add" rows of §9: `drop.maxVelocity` and the 450 px/s no-bounce threshold, board thump, **soft trauma stacking** (`ScreenShake.add` is still additive + clamp), the reduced-motion shake scale, the `hitStop` set, zoom punch, the ≤ 3 flashes/s cap, and the `coins` block.

8. **KTX2.** If GPU-compressed textures ship, copy the Basis/KTX2 transcoders into `public/` and point the setters at relative paths (`tools/qa/approval.mjs` will catch any CDN request).
